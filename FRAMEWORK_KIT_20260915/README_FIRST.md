## 一、KIT 规则（包宪法 · 所有者钦定，违反任何一条即打包/使用失效）

### A · 物理规则（硬约束）

| # | 规则 | 原因/处置 |
|---|---|---|
| A1 | **文件数 <100（硬上限 99）。当前 98/99，余量 1。** | 所有者的入库方式=**把整个文件夹直接拖进库**；≥100 无法整夹拖拽。每次打包必须在 MANIFEST 记录「N/99 余量 M」 |
| A2 | **超限处置=物理合并或淘汰，禁拆多包。** | 先例：v1.2.1 将三大框架+季度包合并为 4 个 COMPENDIUM；低值/过期件移出（zip 内不留死文件）。**永远只有一个 zip** |
| A3 | **每周日期命名制（#108 所有者钦定·宪法附注 13）**：每周更新一次，直接以当日日期命名 `FRAMEWORK_KIT_YYYYMMDD.zip`（不沿用固定主名）；`kits/` 内只保留最新一期，旧版由 git 历史承载；版本演进记 MANIFEST 版本史。**自动顺延条款**：若当周五/六/日未跑数据或所有者未提及 → 自动顺延至**下周第一次跑数据时**一并更新 | 节奏对齐数据跑动；多版本并存=歧义源 |
| A4 | **manifest 必须入包 + `unzip -tq` 完整性测试必须通过**才可提交 | 包内自描述，防丢清单 |
| A5 | 文件名一律英文（内容可中文） | 约束 7 |

### C · 适配条件（移植新标的必读 —— 本框架原生样本=HPE）

**样本特征假设（全部是 HPE 标定，不是普适常数）**：期权链 15 个到期（周权+月权+季度+1 月 LEAPS）/ IV 60%+ 且历史分位 P91（买方禁买环境）/ CSP 门槛 $2.30、触发 spot≤52 / G5 期限 ≥12 月（恢复分布 p90 标定）/ 机会价地图 52/48-49.5/44.5-46/42（MA+ATR+筹码标定）/ 周四无链符号等挂牌制细节。

**agent 拿到任何新标的，必须做完五步适配才可用本框架：**
1. **标的画像五查**：①期权链存在性与到期结构（有无周权/月权/LEAPS·几档）②IV 绝对水平与历史分位 ③OI 与点差深度（流动性门槛）④事件日历（财报季/除息/特殊事件）⑤股息与公司行动史（ex-div 对 put 定价、拆股）。
2. **参数全重算**（templates/ 填槽）：T 阶梯/机会价地图/CSP 门槛与触发价/G5 期限/CC 档位/买 CALL 的 H1-H4 触发价/保证金口径——**逐个重算，禁止照抄 HPE 数字**。
3. **结构适配**：无期权链→⑫驾驶舱降级为纯正股车道；薄链→仅月权 backbone；高 IV→卖方优先/买方禁；低 IV（W 分位≤40%）→买方车道才重开；有股息→put 定价与轮动节奏修正。
4. **适配 diff 留痕**：log 专行记录「哪些参数重算/哪些结构降级/依据什么数据」。
5. **结论永不复制**：HPE 的 62.09 / 52 / 48-49.5 / $2.30 / C70 / 判词 16 条……全部留在样本层。

### D · 使用治理（七条铁律）

1. **复制流程账本，重算参数，永不复制结论**。
2. **一票一库**——一个标的一个库，禁组合话术；新标的=新库+卡E 安检→冷启动。
3. **历史只增不删**——修正=勘误链（#35→#81→#82 先例），禁反向改写。
4. **参数归用户，判据归体系**——改参走三问；判据不随行情松动。
5. **每条建议预设对错判据，每个论点写破坏条件**——缺档标「待补」不伪造。
6. **机械防线优于口头约定**——面板重刻必跑 `panel_check.py`（非 0=禁提交）；每轮入库走 INTEGRITY_AUDIT_METHOD。
7. **行情锚=官方 OHLC；口述只覆盖自身成交**——外部数字过卡H五关（时点/口径/实测/归属/叙事）。

### E · 违规判定清单（出现即失效，须返工）

① 打包 ≥100 文件；② 拆多 zip 或 `kits/` 内留存多期（只保留最新一期）；③ 把 HPE 样本数字当新标的参数或实时报价执行；④ 复制结论不重算；⑤ 改历史判词/删日志行；⑥ 跳过 panel_check 或审计直接提交；⑦ 对话原话未提纯入包；⑧ 丢 manifest 或完整性测试不过。

## 二、仓库运行逻辑（深度文档化 —— B2 规则的落体）

**读库顺序**：宪法 → AGENT-README（会话态快照）→ HANDOFF（体系交接）→ `journal/logic_baseline.md`（活性判词）→ 作战面板（对照件）→ 深档案（三卷/玩法页/专项报告）。**冲突以决策日志为准。**

**模块分工**：`journal/`=时序账本（decision_log 主线 / t_log 做 T 腿 / wheel_log 轮动引擎 / logic_baseline 判词）；`docs/`=长期资产（面板/玩法页/三卷/画像/协议）；`data/`=锚（官方 OHLC、链快照、筹码、RS）；`reports/`=专题报告；`scripts/`=防线与工具（panel_check / 审计法 / RS 周更 / 筹码 v5.2 / 期权引擎）。

**决策闭环**：数据锚（官方 OHLC+链快照）→ 判据应用（六闸/七档/⑪/⑫）→ 决策入 log（含对错判据）→ 面板对照件刷新 → 轮末审计（R1 知识点 grep 对账+R2 数字反验）→ 勘误链 → 下一轮。

**防线机制**：panel_check（面板模块完整性，非 0=禁提交）/ INTEGRITY_AUDIT_METHOD（每轮知识点对账+数字反验）/ 勘误只增不删 / 沙箱重置预案（fetch 显式 refspec→核 diff→恢复）。

**衔接指针**：每轮结束 README/HANDOFF/CHANGELOG/log 四处指针同步刷新；触发词契约（跑一下/拉链/咋玩/结算/周报/复职）由 README 与面板登记。
