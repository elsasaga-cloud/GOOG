# HPE JSON 报告逻辑说明

**对应实现：** `options/options_engine.py`  
**生成文件：** `HPE_量化分析及期权策略.json`  
**性质：** 机器可读的单次期权策略运行快照，不是长期基本面 thesis 的替代品。

## 1. 总体分层

JSON 由一次运行的以下信息组成：

```text
持仓事实源 → 量化信号 → 策略选择 → 行情/期权链 → 合约评分
→ 执行决策 → IV/GARCH 对比 → JSON 快照
```

长期研究结论仍以 `thesis.md` 和 `reports/HPE/<date>/05_321_final_conclusion.md` 为准。期权线服从 thesis：如果财报或其他事件破坏 HPE 基本面论点，期权策略整体停摆并重评。

## 2. JSON 顶层字段

| 字段 | 来源/逻辑 | 用途 |
|---|---|---|
| `run_time` | 运行时本地时间 | 标识快照时间 |
| `strategy` | `CC` 或 `CSP` | 本次选用的策略 |
| `strategy_reason` | `choose_strategy()` | 记录为什么选择该策略 |
| `position` | `options/positions.py` 单一事实源 | 记录股票、成本、可备兑股数和在场期权 |
| `quant` | `quant_core.run_quant_analysis()` | State、筹码、GBM、HMM、GARCH、方向投票等 |
| `quote` | yfinance 近5日历史行情 | 当前价、昨收、涨跌幅、报价日期 |
| `expiry` / `dte` | 选择不早于目标周五的最近到期日 | 期权周期 |
| `decision` | 过滤后的合约、时间、财报窗口和权利金门槛 | `DO`、`WAIT` 或 `SKIP` |
| `primary` | 合约排序后的主候选 | 非执行承诺，只是候选合约 |
| `backup` | 比主候选更保守的备选合约 | 辅助人工决策 |
| `top5` | 排序后的前五合约 | 保留审计轨迹 |
| `iv_vs_garch` | ATM IV 与 GARCH 预测比较 | 判断期权权利金相对贵/薄 |
| `otm_adjust` | 方向信号驱动的 OTM 区间 | 记录区间、目标和调整原因 |

## 3. 持仓感知逻辑

`positions.py` 是唯一事实源。引擎会：

1. 读取当前股票数量、平均成本、在场期权和财报日期；
2. 计算已被在场 CALL 占用的股票数量；
3. 计算可以新开的备兑 CALL 张数；
4. 如果可备兑股数不足一张，自动把策略切换为 CSP，并提示需要先平掉在场 CALL；
5. 如果处于财报日前后 `EARNINGS_WINDOW_DAYS` 禁开窗口，自动阻止新开仓。

当前仓库记录的持仓中，CALL75 占用全部 100 股，因此自动策略下 `CC` 可开张数为 0；该设计是为了防止卖出裸 CALL，而不是判断 HPE 看跌。

## 4. 策略选择逻辑

### 强制模式

- `--mode cc`：强制选择 CC，但仍受可备兑和财报窗口硬风控；
- `--mode csp`：强制选择 CSP，但仍受财报窗口和合约筛选约束。

### 自动模式

```text
如果可备兑股数不足一张 → CSP
否则：
    量化看涨 → CSP
    量化看跌 → CC
    方向不明 → CC
```

背后的经济含义：

- 看涨时，卖 CALL 可能限制上行，因此倾向卖 CSP；
- 看跌时，卖 CSP 接股风险增加，因此倾向 CC；
- 方向不明时，默认用 CC 为现有股票增强收益。

这只是短周期战术逻辑，不能替代 HPE 长期 thesis。

## 5. 价格状态、时间状态和 OTM 调整

### 价格状态

依据当前价相对昨收：

- `strong_up`：涨幅至少1.5%；
- `mild_up`：涨幅至少0.6%；
- `strong_down`：跌幅至少1.5%；
- `mild_down`：跌幅至少0.6%；
- 其余为 `flat`。

价格方向会影响主候选筛选。例如看跌时，CSP 倾向选择更深 OTM 的 Put，看涨时 CSP 可以适当贴近现价。

### 时间状态

- 周末：只做下周预案；
- 周一/周二：默认等待；
- 周三：主操作日；
- 周四：补单日；
- 周五：默认不开新仓；
- DTE≤1：不执行。

### OTM 区间

默认 OTM 区间为1%至5%，目标3.5%。强/弱方向信号会调整上下限；调整结果写入 `otm_adjust`，避免只保存最终价格而丢失决策原因。

## 6. 合约过滤和排序

合约必须经过以下筛选：

- Mid 至少 $0.05；
- 单张权利金达到候选门槛；
- OTM 不超过8%，ITM不超过1%；
- OI至少20或成交量至少10；
- 低OI且价差超过40%时剔除；
- 根据目标 OTM、权利金、OI、成交量、价差、时间状态和价格状态打分。

排序分数主要由以下部分组成：

```text
OTM接近目标分
+ OTM落在偏好区间的分
+ 权利金分
+ OI分
+ 成交量分
+ 时间窗口分
+ 行情方向偏好分
- 宽价差扣分
- ITM风险扣分
```

`primary` 是规则排序的候选，不是自动下单指令。只有 `decision.decision == "DO"` 才进入可执行状态，实际下单仍需人工确认实时价格、流动性、保证金和财报风险。

## 7. 决策状态

| 状态 | 含义 |
|---|---|
| `DO` | 非财报禁开窗口、时间和权利金等条件满足，可人工考虑执行 |
| `WAIT` | 主要是周末或周一/周二观察期，等待更合适的操作日 |
| `SKIP` | 财报禁开、强下跌、没有合约、DTE过短、权利金不足或 CC 无备兑 |

硬门槛包括：

- 财报日前后7天禁开新仓；
- CC 必须有足够备兑股票；
- 周五默认不开新仓；
- DTE≤1 不执行；
- 权利金低于 $15 不执行；
- 强烈下跌时 CSP 倾向跳过或选择更深 OTM。

## 8. IV 与 GARCH

引擎比较期权链 ATM IV 与 GARCH 预测的7日平均年化波动：

- ATM IV 比 GARCH 高5个百分点以上：期权相对贵，卖方条件较好；
- 低5个百分点以上：权利金偏薄；
- 其余：定价大致合理。

财报期间 IV 较高不代表风险消失。它只说明市场为波动支付了更高价格；若基本面 thesis 被证伪，期权线必须停摆。

## 9. 与 HPE 321 研究线的关系

| 研究线 | JSON/期权线 |
|---|---|
| 判断 HPE 是否值得长期拥有 | 判断本周是否有合适的 CC/CSP |
| 财报后全量刷新 | 周三主操作日运行 |
| 依据 thesis、三框架、321综合 | 依据短期量化信号和期权链 |
| 重点看 T1 网络 margin、T3 FCF、T4 AI订单/毛利 | 重点看方向、IV、OTM、OI、时间窗口 |

**优先级规则：** 长期 thesis > 财报作战卡 > 期权 JSON 的短期信号。JSON 中的 `DO` 不能覆盖 thesis 的 `❌`，也不能把“期权贵”解释为“公司便宜”。

## 10. 当前 HPE 决策的联动说明

结合 2026-08-16 研究快照：

- 321 综合57.6，结论为“基本合理偏高”；
- T1 网络 margin 为⚠️，需后续回升验证；
- T3 FY26 FCF≥$3.5B 为✅；
- T4 AI订单与毛利为✅；
- 现价远离主要筹码区，$47-$50 是研究线主要赔率区；
- 低成本持仓者可以继续观察和持有，但新资金不应因短期量化信号而追高。

因此，任何未来 JSON 快照都应被解释为：

> **短周期执行辅助工具；不是对 HPE 长期价值的独立结论。**
