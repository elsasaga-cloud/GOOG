# HPE 质变观察框架与首版台账（2026-09-06）

> 来源：用户方法论声明（如实入账）——"问 Claude 还是为了探究基本面；一个股成长起来需要时间，我愿意长期拿；这个过程中大事项肯定要观察研究和记录，看是否有质变。从 Q2、Q3 到这些合作，能看到在变化；是否质变目前还不好说，但财务数据和管理层动作都在说明一切都在变好中。"
> 本文档=长期底仓型车道（#36）的配套观察协议：把"变好"拆成**量变（可累积）**与**质变（可判定）**，给质变立五个可证伪标记，并建台账。不新增买卖判据（判据归体系），只新增观察纪律。

---

## 0. 结论先行

1. **当前判定：量变充分进行时，质变=候选期未确认**。"一切都在变好中"在数据上成立；但按本框架的硬标准（跨周期存活+多维独立确认），质变还不能盖章。
2. **量变→质变的翻译**：量变=兑现（Q2/Q3 的增速、订单、GM、合作）；质变=**兑现信用被市场持久重定价且 survives 一次下行考验**（#35 情景树里 B 情景"交付不重估"就是"量变不成质变"的形态——本框架正是对最大真实风险的正面回答）。
3. 五个质变标记目前：利润结构🟡推进中 / 收入性质🟡早期 / 客户关系🟢已发生单点 / 市场定价框架🔴未发生 / 业务身份🟡进行中。**没有任何一个是红的（反向证据），也还凑不齐确认质变所需的≥3 个绿。**
4. 维护方式：每个大事项入 decision_log 时顺手打标（量变/质变候选）；季度复核一次标记状态；与 #36 价值锚维护协议共用数据源，不重复劳动。

## 3. 判定规则（防"感觉在变好"）

- **质变盖章 = ≥3 个标记确认 + 跨周期存活**（经历一次 ≥20% 回调或行业逆风后，标记不退回）。
- 时间尺度与用户一致：成长需要时间——**以季为单位复核，不以日为单位投票**；预期 12-24 个月才有第一批盖章可能（最快：标记1+2 在 FY27 中报、标记4 需跨一次考验）。
- 每次盖章/降级 → decision_log 立条 + 中枢矩阵（#36 敏感性）同步重读：质变确认 ≠ 立即调中枢，但 16x bull 档从"情景"变"路径"。

## 5. 维护协议

- 大事项入 decision_log 时打标（量变/候选/确认/反向），一行成本，不加轮次；
- 季度复核（10-Q 后 + 财报后）：五标记状态刷新，本台账追加行（只增不删）；
